# HireTrack – Interview Process Tracking System

A web app that helps a company manage job descriptions and move candidates through
the interview stages: **Profiling → Screening → L1 Technical → L2 Technical → HR Round**.

There are three roles:

| Role | What they can do |
|---|---|
| **HR** | Create/edit/close jobs, create candidate profiles, add and activate panel members, schedule L1/L2 interviews (1–2 panel members), read all feedback, move candidates to the next stage, reject at any stage, make the final decision with comments, search and filter candidates |
| **Panel member** | See only their assigned interviews: candidate profile, resume, JD and focus areas. Submit feedback once (comments, strengths, weaknesses, areas covered, rating 1–5, Selected/Rejected) |
| **Candidate** | Register (logged in straight away, no verification email), apply to **one** job with a PDF resume, track their stage, status and interview schedule (never the panel feedback) |

### Frontend features
- Clean, responsive design with Tailwind (works on phones, tablets and desktops)
- Light, warm colour theme (terracotta accent, cream background, warm greys) by default
- **Dark mode slide switch** in the top bar (and in the phone menu). It remembers your choice
- Toast messages, confirmation pop-ups, loading skeletons, empty states
- Form errors from the server are shown under the matching field
- HR dashboard with stat cards, a clickable hiring pipeline, search, filters and paging
- Stage progress stepper, star ratings for feedback, drag-and-drop resume upload

Each request goes **route → auth/role check → validation → service → Prisma → PostgreSQL**.
Any error is caught by `errorHandler.js` and returned as JSON like
`{ "error": "...", "details": {...} }`.

## How to run it

### 1. Install
- [Node.js 22 LTS](https://nodejs.org)
- [PostgreSQL 16 or 17](https://www.postgresql.org/download/windows/). Remember the password you set for the `postgres` user.

### 2. Create the database
In pgAdmin, create a database named `interview_tracker`, or run:
```powershell
psql -U postgres -c "CREATE DATABASE interview_tracker;"
```

### 3. Configure
```powershell
cd backend
Copy-Item .env.example .env
```
Open `.env` and set:
- `DATABASE_URL`: put your postgres password in place of `YOUR_DB_PASSWORD`.
- `JWT_SECRET`: any long random string.
- `SMTP_*`: see **Email setup** below.
- `SEED_HR_NAME` / `SEED_HR_EMAIL` / `SEED_HR_PASSWORD`: the HR login and the name shown for it.

### Email setup (send from your Gmail)
1. Turn on **2-Step Verification** for your Google account (Google Account → Security).
2. Open <https://myaccount.google.com/apppasswords>, create an app password named
   "HireTrack", and copy the 16-letter code. Gmail does **not** accept your normal password here.
3. In `backend/.env` set:
   ```
   SMTP_HOST="smtp.gmail.com"
   SMTP_PORT=465
   SMTP_USER="your.address@gmail.com"
   SMTP_PASS="the 16-letter app password (spaces are fine)"
   MAIL_FROM="HireTrack <your.address@gmail.com>"
   ```
4. Check it:
   ```powershell
   npm run email:test -- your.address@gmail.com
   ```
   You should see `✔ Test email sent`. When the server starts, it also logs
   `Email (SMTP) ready` or tells you exactly what is wrong.

Gmail allows about 500 emails a day, which is plenty for this project. If you would rather not
send real emails while testing, use a free [Mailtrap](https://mailtrap.io) inbox instead
(copy its SMTP host, port, username and password into the same four settings).

| Problem | Fix |
|---|---|
| `Invalid login` / `Username and Password not accepted` | Use the App Password, not your Gmail password. Check 2-Step Verification is on. |
| `Email is NOT set up` | `SMTP_PASS` still has the placeholder value. |
| `ECONNREFUSED` / timeout | Wrong host or port, or a firewall blocks port 465. Try `SMTP_PORT=587`. |
| Email arrives in Spam | Normal at first. Mark it "Not spam". |
| Links in the email open the wrong address | Set `APP_URL` to the address people use to open the site. |

### 4. Install packages, create tables, add the HR user
```powershell
npm install
npx prisma migrate dev
npm run db:seed
```

### 5. Start
```powershell
npm run dev
```
Open **http://localhost:8080**. The backend also serves the frontend pages.

### 6. Changing the design (only when you edit classes)
`frontend/css/output.css` is already built, so the site works without this step.
If you add or change Tailwind classes, rebuild the CSS in a second terminal:
```powershell
cd frontend
npm install
npm run watch:css
```
`watch:css` rebuilds automatically every time you save. Use `npm run build:css` for a one-time build.

### Google sign-in setup (optional)
Adds a **Continue with Google** button to the login and register pages.
1. Go to <https://console.cloud.google.com/apis/credentials> (create a project if asked).
2. **OAuth consent screen**: choose *External*, fill in the app name and your email, and add your
   Gmail as a *Test user*.
3. **Create credentials → OAuth client ID → Web application**.
   Under **Authorized JavaScript origins** add `http://localhost:8080`.
4. Copy the **Client ID** (ends with `.apps.googleusercontent.com`) into `backend/.env`:
   `GOOGLE_CLIENT_ID="....apps.googleusercontent.com"`, then restart the server.

Rules: candidates can sign up with Google straight away (no password needed).
HR and panel members can use Google only with the email HR already added; nobody becomes HR by
signing in with Google. The Client ID is not a secret; no Client Secret is needed.

### Account emails
Every email starts with "Dear {name}," and ends with "Warm regards, HR Team":
candidate account created by HR, password reset, interview scheduled, application updates
(with a kind message for selected / not selected), panel welcome + login details, and
new interview assigned (to the panel member).

## Try the full flow

1. Log in as HR (the seed email and password) and create a job on **Jobs**.
2. Open the homepage in a private window, click **Register**; you are logged in straight away.
3. Click **Apply** on the job and fill in the form with a PDF resume. The status becomes *Profiling Completed*.
4. As HR, go to **Panels**, add two panel members and click **Activate & email login**. Each gets a
   welcome email with their login email and a temporary password. On their first login they must
   choose their own password. (Lost it? HR clicks **Resend login** to email a new one.)
5. As HR, open the candidate and click **Move to next stage** twice to reach L1 Technical. Then schedule the L1 interview.
6. Log in as a panel member and submit feedback on **My Interviews**.
7. As HR, move the candidate on to L2, then to the HR Round, and make the final decision.
8. As the candidate, open **My Application** to see the stage, status and schedule. Feedback is never shown there.

## API summary

Base URL `/api`. Protected routes need the header `Authorization: Bearer <token>`.

| Method | Endpoint | Who |
|---|---|---|
| POST | `/auth/register` (returns login token), `/auth/login`, `/auth/set-password`, `/auth/forgot-password` | Public |
| POST | `/auth/google` (Google sign-in token) · GET `/auth/config` | Public |
| GET / POST | `/auth/account`, `/auth/change-password` | Any logged-in user |
| GET | `/jobs`, `/jobs/:id` | Public |
| GET | `/jobs/all` | HR |
| POST / PUT | `/jobs`, `/jobs/:id` | HR |
| PATCH | `/jobs/:id/close`, `/jobs/:id/reopen` | HR |
| POST | `/candidates` (multipart, file field `resume`) | HR, Candidate |
| GET | `/candidates?jobId&stage&status&search&page&size` | HR |
| GET | `/candidates/stats` | HR (dashboard counts) |
| GET | `/candidates/me` | Candidate |
| GET | `/candidates/:id` | HR, assigned Panel |
| GET | `/candidates/:id/resume` | HR, assigned Panel, the Candidate |
| POST | `/candidates/:id/next-stage`, `/reject`, `/final-decision`, `/interviews` | HR |
| POST / GET | `/panels`, `/panels/:id/activate` (activate or resend login details) | HR |
| GET | `/interviews/mine` | Panel |
| POST | `/interviews/:id/feedback` | Panel |
